# Every pre-commit hook is pinned to a mutable git tag

## Problem

Classes: integrity-gap / install-script on a floating reference. All ten hook repos are referenced
by tag (`rev: v6.0.0`, `rev: "3.3.26"`, …). A git tag can be moved; pre-commit/prek fetches whatever
commit the tag points to at install time, then runs that repo's install step (pip install, go
install, npm install, docker pull) and its hook code with the contributor's privileges. There is no
lockfile and no hash.

## Evidence

Source: .pre-commit-config.yaml:4 `rev: v6.0.0`, :23 `rev: v0.0.5`, :28 `rev: v1.0.0-rc.4`, :41
`rev: v0.21.0`, :46 `rev: v0.49.1`, :52 `rev: v1.38.0`, :57 `rev: v3.13.1-1`, :62 `rev: v0.11.0`,
:68 `rev: v1.7.12`, :74 `rev: "3.3.26"`. Hook languages at those revs include python (shfmt,
checkov), golang (actionlint), node (markdownlint-cli) and docker_image (shellcheck), each of which
runs an install. The workflow side of the repo pins every action by 40-char SHA, so this is the one
supply-chain surface left on tags.

## Impact

A compromised or retagged hook repository executes attacker code on every contributor machine at the
next `prek install`/autoupdate or cache miss, with access to the user's SSH keys — the exact
material this tool exists to protect.

## Fix

Freeze the revs to commit SHAs with the tag kept as a comment:

```bash
prek autoupdate --freeze
```

This rewrites each entry to `rev: <40-char sha>  # frozen: vX.Y.Z`. Renovate's pre-commit manager
is enabled in the shared preset, but its documentation does not state that it updates frozen
revs; confirm on one Renovate PR after freezing, and otherwise run `prek autoupdate --freeze`
periodically in place of Renovate for this file.

Open (2026-10-27 run): freezing was offered at the fix prompt and not approved. The hook revs were
updated to their latest tags in the same run.
